# Test catalog

## English

The **Test catalog** page lists the national list of tests: code, name, category, specimen types, LOINC code (or **No LOINC**) and whether this lab runs each test. You need Terminology view to open it and Terminology manage to change anything.

An install that did not receive its catalog from central owns it, and can add, edit, retire and restore tests. A lab that receives the catalog from central cannot change its tests. It can switch tests on or off, narrow their specimens and set a local name. Sync never sends those settings.

Add a test from the page's ⋯ menu, and edit one from its row's ⋯ menu. The same row menu switches a test on or off at this lab, and retires or restores it. Search matches the code, name, short name and local name. Filter by category, LOINC, on or off, and status. Retired tests are hidden unless you filter for them.

A LOINC code is searched when LOINC is loaded on this install. Otherwise it is typed, and only its format is checked. Specimen types come from CE's specimen-type list, and categories from **Test categories** on the Terminology page.

Import a national list from a CSV or Excel (.xlsx) file with **Import** in the page's ⋯ menu, where this install owns the catalog. The sheet reads the file, matches its headers to the fields for you to check, asks what each unmatched category or specimen means, and shows new, changed, unchanged and refused rows before anything is written. A file holds at most 5,000 tests. Tests match on their code, so the same file twice changes nothing, and a test missing from the file is not retired. **Export CSV** writes the active tests in the same columns, so an export imports back as it is.

The Lab order's Tests field lists the catalog tests switched on at this lab, under their local names, and each chosen test carries its own specimen, from the specimens that test accepts. A submitted order lists each test's LOINC code first, then its catalog code, so reports that read an order's first code keep matching LOINC. Switch tests on before taking orders: an empty list lets no order through.


A test can also name the result parameters it yields, each with a result type and, for a numeric one, reference bands by sex and age. The bench sees the band that fits the patient. A range can be named, and the bench picks which range applies to each result.

Lab systems name tests their own way, so map each lab test code to the catalog test it means. Open the **Observed** tab, which lists every test code in the warehouse with its requests and last seen date, and filter by **Unmapped**, **Mapped** or **Ambiguous**. Choose **Map to catalog test** from a row's ⋯ menu, pick the test, then choose **Save** from the sheet's ⋯ menu. A code with two catalog mappings is **Ambiguous**, and reports leave it out until you map it again. When central has mapped a code, central's mapping is the one reports use, and a lab's own mapping for that code is ignored. A lab cannot change a mapping central sent down (**From central**). Codes match the way the warehouse database compares text. On Postgres that is exact, so `HIVVL` and `HIVVL ` with a trailing space are two codes. On MSSQL and MySQL with their default settings, case is ignored, and MSSQL also ignores trailing spaces. On MSSQL and MySQL, two mappings whose codes differ only by case (`HIVVL` and `hivvl`) collide in `test_map`, and every rebuild fails until one is cleared. Map only one of them. **Export CSV** and **Import CSV** in the tab's ⋯ menu map many codes at once: fill in `catalog_code`, or `loinc` when you know only that. The import shows new, changed, unchanged and refused rows before it writes. A row is refused when the warehouse holds the code only with surrounding spaces, because the file reader trims cells. On a lab, a row whose code central has mapped is refused unless it asks for the mapping central already has. Mappings are copied to the warehouse table `test_map`. A report joins it on `tm.level = 'test'`, `tm.source_system = lr.panel_system` and `tm.source_code = lr.panel_code`. The copy updates when a mapping or a catalog test changes, and at start-up. If an update fails, choose **Rebuild warehouse copy**.

Result codes map the same way, to fields of the site's result dictionary. Import a dictionary with `openldr terminology import parameters <file>`. The **Result fields** tab lists each field with its role, units and LOINC code, and links a field to LOINC from its row's ⋯ menu, or many at once by CSV (`code`, `loinc`). On the **Observed** tab, choose **Results** to list the result codes in the warehouse, and map one with **Map to result field**. **Map matching codes** maps every unmapped code of one lab system to the field with the same code, which covers most codes on a DISA site. Results and orders entered in CE need no mapping: the warehouse copy maps each field and each catalog test to itself. A report joins result codes on `tm.level = 'result'`, `tm.source_system = l.observation_system` and `tm.source_code = l.observation_code`, and can filter on `tm.loinc`. A content pack ships result mappings with a `result-mappings` step.

## Français

La page **Catalogue des examens** présente la liste nationale des examens : code, nom, catégorie, types de prélèvement, code LOINC (ou **Sans LOINC**) et si ce laboratoire réalise chaque examen. Il faut la permission de consulter la Terminologie pour l'ouvrir, et celle de la gérer pour modifier quoi que ce soit.

Une installation qui n'a pas reçu son catalogue du site central en est propriétaire et peut ajouter, modifier, retirer et rétablir des examens. Un laboratoire qui reçoit le catalogue du site central ne peut pas modifier ses examens. Il peut activer ou désactiver des examens, restreindre leurs prélèvements et définir un nom local. La synchronisation n'envoie jamais ces réglages.

Ajoutez un examen depuis le menu ⋯ de la page, et modifiez-en un depuis le menu ⋯ de sa ligne. Ce même menu active ou désactive un examen dans ce laboratoire, et le retire ou le rétablit. La recherche porte sur le code, le nom, le nom court et le nom local. Filtrez par catégorie, LOINC, activé ou non, et statut. Les examens retirés sont masqués, sauf si vous filtrez sur eux.

Un code LOINC est recherché quand LOINC est chargé sur cette installation. Sinon il est saisi, et seul son format est vérifié. Les types de prélèvement viennent de la liste des types de prélèvement de CE, et les catégories de **Test categories** sur la page Terminologie.

Importez une liste nationale depuis un fichier CSV ou Excel (.xlsx) avec **Importer** dans le menu ⋯ de la page, si cette installation est propriétaire du catalogue. Le panneau lit le fichier, associe ses en-têtes aux champs pour que vous les vérifiiez, demande ce que signifie chaque catégorie ou prélèvement sans correspondance, et montre les lignes nouvelles, modifiées, inchangées et refusées avant toute écriture. Un fichier contient au plus 5 000 examens. Les examens sont rapprochés par leur code : le même fichier importé deux fois ne change rien, et un examen absent du fichier n'est pas retiré. **Exporter en CSV** écrit les examens actifs dans les mêmes colonnes, pour qu'un export s'importe tel quel.

Le champ Tests de la demande d'examens liste les examens du catalogue activés dans ce laboratoire, sous leurs noms locaux, et chaque examen choisi porte son propre prélèvement, parmi ceux que cet examen accepte. Une demande envoyée donne d'abord le code LOINC de chaque examen, puis son code du catalogue, pour que les rapports qui lisent le premier code d'une demande trouvent toujours LOINC. Activez des examens avant de prendre des demandes : une liste vide ne laisse passer aucune demande.


Un examen peut aussi nommer les paramètres de résultat qu'il produit, chacun avec un type de résultat et, pour un paramètre numérique, des intervalles de référence par sexe et par âge. La paillasse voit l'intervalle qui correspond au patient. Un intervalle peut porter un nom, et la paillasse choisit celui qui s'applique à chaque résultat.

Les systèmes de laboratoire nomment les tests à leur façon : associez donc chaque code de test du laboratoire au test du catalogue qu'il désigne. Ouvrez l'onglet **Observés**, qui liste tous les codes de test de l'entrepôt avec leurs demandes et la date où ils ont été vus pour la dernière fois, et filtrez par **Sans correspondance**, **Avec correspondance** ou **Ambigu**. Choisissez **Associer à un test du catalogue** dans le menu ⋯ d'une ligne, choisissez le test, puis **Enregistrer** dans le menu ⋯ du panneau. Un code qui a deux correspondances avec le catalogue est **Ambigu**, et les rapports l'ignorent tant que vous ne l'avez pas associé de nouveau. Quand le central a associé un code, c'est la correspondance du central que les rapports utilisent, et celle du laboratoire pour ce code est ignorée. Un laboratoire ne peut pas modifier une correspondance envoyée par le central (**Du central**). Les codes sont comparés comme le fait la base de données de l'entrepôt. Sur Postgres, la comparaison est exacte : `HIVVL` et `HIVVL ` avec une espace à la fin sont deux codes. Sur MSSQL et MySQL avec leurs réglages par défaut, la casse est ignorée, et MSSQL ignore aussi les espaces à la fin. Sur MSSQL et MySQL, deux correspondances dont les codes ne diffèrent que par la casse (`HIVVL` et `hivvl`) entrent en conflit dans `test_map`, et chaque reconstruction échoue tant que l'une n'est pas supprimée. N'associez qu'une seule des deux. **Exporter en CSV** et **Importer un CSV**, dans le menu ⋯ de l'onglet, associent plusieurs codes à la fois : remplissez `catalog_code`, ou `loinc` quand vous ne connaissez que celui-ci. L'import montre les lignes nouvelles, modifiées, inchangées et refusées avant d'écrire. Une ligne est refusée quand l'entrepôt ne contient le code qu'avec des espaces autour, car le lecteur de fichier supprime les espaces des cellules. Dans un laboratoire, une ligne dont le code est associé par le central est refusée, sauf si elle demande la correspondance que le central a déjà. Les correspondances sont copiées dans la table d'entrepôt `test_map`. Un rapport la joint avec `tm.level = 'test'`, `tm.source_system = lr.panel_system` et `tm.source_code = lr.panel_code`. La copie se met à jour quand une correspondance ou un test du catalogue change, et au démarrage. Si une mise à jour échoue, choisissez **Reconstruire la copie de l’entrepôt**.

Les codes de résultat s'associent de la même façon, aux champs du dictionnaire de résultats du site. Importez un dictionnaire avec `openldr terminology import parameters <fichier>`. L'onglet **Champs de résultat** liste chaque champ avec son rôle, ses unités et son code LOINC, et lie un champ à LOINC depuis le menu ⋯ de sa ligne, ou plusieurs à la fois par CSV (`code`, `loinc`). Dans l'onglet **Observés**, choisissez **Résultats** pour lister les codes de résultat de l'entrepôt, et associez-en un avec **Associer à un champ de résultat**. **Associer les codes identiques** associe chaque code sans correspondance d'un système de laboratoire au champ qui porte le même code, ce qui couvre la plupart des codes sur un site DISA. Les résultats et les demandes saisis dans CE n'ont pas besoin de correspondance : la copie de l'entrepôt associe chaque champ et chaque test du catalogue à lui-même. Un rapport joint les codes de résultat sur `tm.level = 'result'`, `tm.source_system = l.observation_system` et `tm.source_code = l.observation_code`, et peut filtrer sur `tm.loinc`. Un pack de contenu fournit des correspondances de résultats avec une étape `result-mappings`.

## Português

A página **Catálogo de exames** mostra a lista nacional de exames: código, nome, categoria, tipos de amostra, código LOINC (ou **Sem LOINC**) e se este laboratório realiza cada exame. Precisa da permissão de ver a Terminologia para a abrir, e da permissão de a gerir para alterar qualquer coisa.

Uma instalação que não recebeu o catálogo do nível central é dona dele, e pode adicionar, editar, retirar e repor exames. Um laboratório que recebe o catálogo do nível central não pode alterar os seus exames. Pode ativar ou desativar exames, restringir as suas amostras e definir um nome local. A sincronização nunca envia essas definições.

Adicione um exame no menu ⋯ da página, e edite-o no menu ⋯ da sua linha. Esse mesmo menu ativa ou desativa um exame neste laboratório, e retira-o ou repõe-no. A pesquisa abrange o código, o nome, o nome curto e o nome local. Filtre por categoria, LOINC, ativado ou não, e estado. Os exames retirados ficam ocultos, exceto se filtrar por eles.

Um código LOINC é pesquisado quando o LOINC está carregado nesta instalação. Caso contrário é escrito, e só o formato é verificado. Os tipos de amostra vêm da lista de tipos de amostra do CE, e as categorias de **Test categories** na página Terminologia.

Importe uma lista nacional de um ficheiro CSV ou Excel (.xlsx) com **Importar** no menu ⋯ da página, quando esta instalação é dona do catálogo. O painel lê o ficheiro, associa os cabeçalhos aos campos para que os verifique, pergunta o que significa cada categoria ou amostra sem correspondência, e mostra as linhas novas, alteradas, sem alteração e recusadas antes de escrever qualquer coisa. Um ficheiro tem no máximo 5000 exames. Os exames são comparados pelo código: o mesmo ficheiro importado duas vezes não muda nada, e um exame que não está no ficheiro não é retirado. **Exportar CSV** escreve os exames ativos nas mesmas colunas, para que uma exportação se importe tal como está.

O campo Tests do pedido de exames lista os exames do catálogo ativados neste laboratório, com os nomes locais, e cada exame escolhido tem a sua própria amostra, entre as que esse exame aceita. Um pedido enviado indica primeiro o código LOINC de cada exame e depois o código do catálogo, para que os relatórios que leem o primeiro código de um pedido continuem a encontrar LOINC. Ative exames antes de receber pedidos: uma lista vazia não deixa passar nenhum pedido.

Um exame também pode nomear os parâmetros de resultado que produz, cada um com um tipo de resultado e, para um numérico, intervalos de referência por sexo e idade. A bancada vê o intervalo que corresponde ao doente. Um intervalo pode ter um nome, e a bancada escolhe qual se aplica a cada resultado.

Os sistemas de laboratório dão nomes aos testes à sua maneira, por isso associe cada código de teste do laboratório ao teste do catálogo que significa. Abra o separador **Observados**, que lista todos os códigos de teste do armazém com os pedidos e a data em que foram vistos pela última vez, e filtre por **Sem correspondência**, **Com correspondência** ou **Ambíguo**. Escolha **Associar a um teste do catálogo** no menu ⋯ de uma linha, escolha o teste e depois **Guardar** no menu ⋯ do painel. Um código com duas correspondências com o catálogo é **Ambíguo**, e os relatórios deixam-no de fora até o associar de novo. Quando o central associou um código, é a correspondência do central que os relatórios usam, e a do laboratório para esse código é ignorada. Um laboratório não pode alterar uma correspondência enviada pelo central (**Do central**). Os códigos são comparados como a base de dados do armazém compara texto. No Postgres a comparação é exata: `HIVVL` e `HIVVL ` com um espaço no fim são dois códigos. No MSSQL e no MySQL com as definições por omissão, as maiúsculas e minúsculas são ignoradas, e o MSSQL ignora também os espaços no fim. No MSSQL e no MySQL, duas correspondências cujos códigos diferem apenas na capitalização (`HIVVL` e `hivvl`) entram em conflito em `test_map`, e cada reconstrução falha até uma delas ser removida. Associe só uma delas. **Exportar CSV** e **Importar CSV**, no menu ⋯ do separador, associam vários códigos de uma vez: preencha `catalog_code`, ou `loinc` quando só conhece esse. A importação mostra as linhas novas, alteradas, inalteradas e recusadas antes de escrever. Uma linha é recusada quando o armazém só tem o código com espaços à volta, porque o leitor de ficheiros apara as células. Num laboratório, uma linha cujo código o central associou é recusada, a não ser que peça a correspondência que o central já tem. As correspondências são copiadas para a tabela do armazém `test_map`. Um relatório junta-a com `tm.level = 'test'`, `tm.source_system = lr.panel_system` e `tm.source_code = lr.panel_code`. A cópia atualiza-se quando uma correspondência ou um teste do catálogo muda, e no arranque. Se uma atualização falhar, escolha **Reconstruir a cópia do armazém**.

Os códigos de resultado associam-se da mesma forma, aos campos do dicionário de resultados do site. Importe um dicionário com `openldr terminology import parameters <ficheiro>`. O separador **Campos de resultado** lista cada campo com a sua função, unidades e código LOINC, e liga um campo ao LOINC no menu ⋯ da sua linha, ou vários de uma vez por CSV (`code`, `loinc`). No separador **Observados**, escolha **Resultados** para listar os códigos de resultado do armazém, e associe um com **Associar a um campo de resultado**. **Associar códigos iguais** associa cada código sem correspondência de um sistema do laboratório ao campo com o mesmo código, o que cobre a maioria dos códigos num site DISA. Os resultados e os pedidos registados no CE não precisam de correspondência: a cópia do armazém associa cada campo e cada teste do catálogo a si próprio. Um relatório junta os códigos de resultado em `tm.level = 'result'`, `tm.source_system = l.observation_system` e `tm.source_code = l.observation_code`, e pode filtrar por `tm.loinc`. Um pacote de conteúdo traz correspondências de resultados com um passo `result-mappings`.
