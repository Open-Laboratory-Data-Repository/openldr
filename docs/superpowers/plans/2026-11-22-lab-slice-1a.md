# Lab module slice 1a: groundwork implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The groundwork the lab module needs, with no change to how existing features behave: coded fields that expand, FHIR Task and Provenance, a lab's own correction path, critical limits, per-lab sections and review settings, lab-wide settings, the lab capabilities and roles, and the seeded lists.

**Architecture:** Each piece goes where its neighbours already live: schemas in `@openldr/fhir`, store functions in `@openldr/db`, rules in `@openldr/bootstrap`, routes in `apps/server`, screens in `apps/studio`, commands in `@openldr/cli`. One migration, 137, adds the per-lab columns and seeds the lists.

**Tech stack:** TypeScript, zod, Kysely on Postgres, Fastify, React with shadcn, vitest, pg-mem.

**Spec:** `docs/superpowers/specs/2026-11-22-lab-module-design.md`, slice 1a in section 7, sections 5.1, 5.2, 5.3 (sample conditions), 5.4 (return reasons), 5.6 (critical limits) and 5.9.

- Since migration 130, `fhir.fhir_resources` is a view: write `fhir.fhir_current` and `fhir.resource_history`.
- Studio: AGENTS.md section 5. Strings in en, fr and pt. Results of an action are sonner toasts, never a status line in the page.
- Shared logic in `@openldr/bootstrap`; route and CLI call the same code. CLI admin commands audit through `cliActor()`.
- No em dashes. No `Co-Authored-By` trailer.
- Gate: `pnpm turbo run test --force --concurrency=2 --continue` and `pnpm turbo run typecheck --force --concurrency=2`, plus `pnpm --filter @openldr/server lint`. Never pipe turbo through `tail`. Never read `$?` through a pipe.

## Review focus

1. An existing install that already imported the FHIR catalog: after this slice, on the next start, `$expand` of administrative-gender returns male, female, other, unknown. (Task 1)
2. A lab correction on a standalone install with no sync site id: it saves, versions and writes a Provenance. (Task 3)
3. A reference band whose critical limits sit inside its normal limits, or whose critical low is not below its critical high: refused with a clear message. Either limit may be given alone. (Task 4)
4. A user without `lab.settings` tries to change a section, a review setting or self-authorisation, through the route and through the served CLI: refused. (Tasks 5 and 6)
5. Migration 137 run twice, and its `down()`: no duplicate concepts, and `down()` removes only what 137 added. (Task 5)

### Task 3: The lab's own correction path

**Files:**
- Modify: `packages/db/src/fhir-store.ts` (the `FhirStore` interface near 113-137; add beside `amend`)
- Test: `packages/db/src/fhir-store-correct.test.ts`, following `packages/db/src/fhir-store-amend.test.ts`

**Interfaces:**
- Produces on `FhirStore`:

```ts
correct(input: {
  resourceType: 'ServiceRequest' | 'Specimen' | 'Observation';
  id: string;
  next: Record<string, unknown>;          // the whole new resource body, same type and id
  who: string;                             // agent.who.display
  reason: string;                          // reason.text, required, trimmed, 1 to 500
  activity?: 'correct' | 'amend';          // v3-DataOperation; default 'correct'
}): Promise<{ resource: Record<string, unknown>; provenanceId: string; version: number }>;
export class CorrectionError extends Error { readonly reason: 'not-found' | 'type' | 'invalid' | 'reason' }
```

How: in one transaction, check the type and that the resource exists, run `validateResource(next)` from `@openldr/fhir`, then `writeMany(trx, [next, provenance], {}, await resolveSiteId(), false)` (near 241) so a null site id works. The Provenance has `target` = the new version, `recorded` = now, `activity` = v3-DataOperation `UPDATE` for correct and `UPDATE` with text "amend" for amend, `agent[0].who.display` = who, `reason[0].text` = reason. No `sync_amendments` rows. Fire `pg_notify` the way `saveMany` does (near 478-490). `amend` is not changed.

- [ ] **Step 1: Write failing tests:** a correction on a store with no site id saves version 2 and a Provenance pointing at it; the history keeps version 1; an unknown id throws `CorrectionError` reason `not-found`; a type outside the three throws `type`; an invalid body throws `invalid` and writes nothing; an empty reason throws `reason`; no `sync_amendments` row is written.
- [ ] **Step 2: Run** `pnpm --filter @openldr/db test -- fhir-store-correct` and see them fail.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** `pnpm --filter @openldr/db test` and typecheck. Expect pass, with `fhir-store-amend.test.ts` unchanged.
- [ ] **Step 5: Commit** `feat(db): a lab corrects its own records, with a Provenance`
