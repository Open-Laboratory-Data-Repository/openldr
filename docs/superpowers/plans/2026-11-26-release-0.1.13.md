# Release 0.1.13, with the Windows desktop build

Goal: a published CE 0.1.13 whose Windows desktop app installs lab-bench 0.6.2 from the public
marketplace. Today the laptop runs desktop 0.1.12, which cannot read lab-bench's manifest.

## Facts this plan rests on

- Last release: `v0.1.12` (2026-11-22). Its GitHub release has the Windows zip
  `openldr-desktop-0.1.12-win32-x64.zip`, the Linux and macOS archives, `SHA256SUMS`,
  `latest.json` and `docker-compose.yml`.
- `main` is 370 commits past `v0.1.12`, 204 of them feat, fix or perf. Migrations 135 to 146 are
  new. `package.json` still says 0.1.12.
- No compose file, install script or `.env.example` changed since `v0.1.12`
  (`git diff --stat v0.1.12..main` over them is empty). So the upgrade guide needs no new step.
- `v0.1.13-rc.1` is main `f9da37cab` plus one version commit, on branch `demo/rc-0.1.13-rc.1`.
  It has no GitHub release and no desktop packages. The droplet runs its images.
- No feature branch is waiting to merge. The branches ahead of main are old demo and rc version
  bumps.
- `pnpm release` runs on this Linux box only. It runs the full gate, builds Studio, the launcher
  and the desktop app, packs all three desktop archives (`pnpm pack:desktop all`), pushes five
  images, installs the published tag into a clean folder to check it, then tags, cuts the release
  and uploads the archives (about 1.7 GB).
- A release candidate is made by hand: a `demo/rc-*` branch that bumps the seven `package.json`
  versions, `scripts/build-and-push.sh` for the images, `pnpm pack:desktop all`, then
  `gh release create --prerelease` with the archives. The plain installer skips a pre-release.
  0.1.12 needed four of them (rc.1 to rc.4) before the Windows app worked.
- The laptop updates by running the Windows installer again. It keeps the data folder:
  `install/desktop.ps1` with `-Version <X.Y.Z>`, or no option for the newest release.

## Steps

### 1. Release candidate 0.1.13-rc.2 (this box)

1. Branch `demo/rc-0.1.13-rc.2` from main. Set the seven `package.json` versions to
   `0.1.13-rc.2`, the same files as `demo/rc3`. Commit.
2. Run the full gate on it, forced, at `--concurrency=2`.
3. `scripts/build-and-push.sh` for the five images at `0.1.13-rc.2`.
4. `pnpm pack:desktop all`. Check `dist/desktop/v0.1.13-rc.2/` holds three archives and
   `SHA256SUMS`.
5. `gh release create v0.1.13-rc.2 --prerelease` with the same body as `v0.1.12-rc.4`, then upload
   `SHA256SUMS` first and the three archives after it.

Done when the pre-release lists four files and `git ls-remote --tags origin` shows the tag.

### 2. Try it on the Windows laptop

Run in PowerShell on the laptop. You do this, or the laptop session does it on your word:

```
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Open-Laboratory-Data-Repository/openldr/main/install/desktop.ps1))) -Version 0.1.13-rc.2
```

Check, in this order:

1. The app starts, and its data from 0.1.12 is still there. Migrations 135 to 146 run on start.
2. Marketplace, Browse: lab-bench 0.6.2 shows **Verified**, the requirements line is green, and
   Install is on.
3. Install lab-bench. The **Laboratory** page opens.
4. One order through to an issued report, then the report opens in CE Reports.

A failure here means a fix on main and another rc (rc.3). No release until step 2 passes.

### 3. Release 0.1.13 (this box)

1. On main: set the seven versions to `0.1.13`, commit, `pnpm make:changelog`, commit, push.
2. `pnpm release --dry-run`, then `pnpm release`.
3. Check the release has `latest.json`, `SHA256SUMS` and the three archives, and that the plain
   installer picks 0.1.13 on the laptop.

### 4. After the release

- The web page `apps/web/src/docs/0.1.8/*/lab-plugin.md` still describes the old `lab` plugin and
  says it is not in the marketplace. Rewrite it for lab-bench in en, fr and pt.
- The droplet runs 0.1.13-rc.1. Moving it to 0.1.13 is a separate step, on your word.

## Not in this plan

- The two issued-edition findings: the HEAD check writes a "reports.issued.read" audit row, and
  the value column wraps on a phone. Neither blocks lab-bench. Fix before step 1 only if you say so.
- macOS and Linux desktop checks. They are packed and uploaded, but only Windows is tried by hand.

## What only a real run proves

- The tag rollback in `pnpm release` has never run (RELEASE.md, "What is NOT proven by tests").
