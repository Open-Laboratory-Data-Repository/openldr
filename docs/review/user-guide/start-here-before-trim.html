Start here

OpenLDR Studio is the browser app for working with your lab's records. Use it to read dashboards, run reports, find patients, enter data and manage how information arrives.

This guide explains the screen, common controls and where to get help. It also introduces the command-line interface for tasks that need server access.

Open Studio

Ask your administrator for the Studio address and your sign-in details. Open that address in a browser and sign in with your organisation's account.

Your first page may be Dashboard, Reports or another page chosen for your account. A link to a specific page opens that page directly.

The menu depends on your permissions and selected layout. A missing page does not always mean the feature is unavailable. Ask your administrator to check your access and layout.

Find your way around

The main menu takes you between areas of Studio. Controls in the page header let you read notifications and change the theme.

Dashboard
Read charts and totals, or create your own.
Reports
Run printable reports and export their results.
Patients
Find a patient and read their requests and results.
Forms
Enter data using published forms.
Query
Browse tables and write read-only SQL queries.
Workflows
Manage how data is received, checked and stored.
Activity
Follow data through its processing stages.
Audit
See who changed settings and other records.
Docs
Open these guides.

Settings is in your user menu at the bottom of the sidebar. Administrators use it for connectors, roles, laboratory details and other install-wide choices.

Find page and editing actions

Look for the dots menu at the top right of a page, beside a table row, or at the top of an editing panel. The actions depend on the page and your permissions.

When an editing panel has a Save action, check its dots menu. Some switches save as soon as you change them. The relevant guide says which behaviour to expect.

Choose the language you want to use in Studio and its guides. Your choice is saved to your account and follows you to other devices.

Use the command line

The command-line interface, or CLI, lets you tell OpenLDR what to do by typing a command in a terminal window. Operators use it to import files, check the installation and perform maintenance.

You can read dashboards, run reports and use forms in the browser. Use the CLI when a guide calls for a command and you have access to the server.

First you will open a terminal, find the installation folder, and ask OpenLDR for help. The installer already includes the CLI. OpenLDR must be installed and running before you use the installed CLI wrapper.

Run commands on the OpenLDR server

A command shown in these guides runs on the computer hosting OpenLDR. The browser's address bar and a Studio search box are not terminals.

If you work remotely, get server access from your administrator first. Opening Studio over Tailscale gives you browser access. It does not provide a command-line session.

My administrator gave me SSH access

SSH is a way to open a secure terminal session on another computer. Use the address, username and sign-in method your administrator provided. Their connection command may look like:

ssh username@server-address

Replace both example values with the details you were given. Run OpenLDR commands after connecting to that server.

1.Open a terminal

Use the instructions for the computer where you will run the command.

Windows
Open Start, search for PowerShell, then open Windows PowerShell.
macOS
Open Terminal from Applications, then Utilities.
Linux
Open your applications menu, search for Terminal, and open it.
Remote server
Connect using the access instructions your administrator supplied.

You will see a prompt with a place to type. Enter a command and press Enter to run it. Copy only the command, without any prompt symbol such as $ or >.

2.Find the installation folder

The installation folder contains docker-compose.yml, a data folder, and the CLI wrapper. The wrapper is named openldr on Linux and macOS, or openldr.ps1 on Windows.

Ask the person who installed OpenLDR for this folder's location if you do not know it. A source checkout uses the repository folder instead.

cd means change directory. Use it to move your terminal into the correct folder. The paths below are examples. Replace them with your actual folder before running a command.

3.Run your first command

Start with help. It lists the available commands. Use the section that matches how OpenLDR was installed.

Linux or macOS, installed with the Docker installer

Move into the installation folder, then ask OpenLDR for help:

cd "/path/to/openldr"
./openldr --help

./openldr means run the OpenLDR wrapper in the current folder.

Windows, installed with the PowerShell installer

In PowerShell, move into the installation folder, then ask for help:

cd "C:\path\to\openldr"
.\openldr.ps1 --help

.\openldr.ps1 runs the Windows wrapper in the current folder.

Running OpenLDR from a source checkout

From the repository root, use the project's CLI command. This assumes the development dependencies are already installed:

cd "/path/to/openldr_ce"
pnpm openldr --help

The pnpm openldr prefix runs the CLI from the source checkout.

Expected result

Look for this usage line and a list headed Commands:

Usage: openldr [options] [command]

Help shows what you can run. It does not import a file.

4.Get help for one command

Add --help after a command name to learn what it accepts. For example, ingest imports a file.

./openldr ingest --help

On Windows, use .\openldr.ps1 ingest --help. From a source checkout, use pnpm openldr ingest --help.

Expected result

Usage: openldr ingest [options] <file>

<file> means you must provide a file path. Replace the placeholder with the real path. Do not type the angle brackets.

Understand commands and file paths

A command has a program, an action, and sometimes a file or options. Here is an example to read before using an import command:

./openldr ingest data/my-file.json
./openldr
Runs the installed CLI wrapper.
ingest
Imports the file into OpenLDR.
data/my-file.json
Names the file to read. Use the name of a real file you intend to import.

For an installed Docker stack, put the file inside the installation's data folder. Use the data/ prefix in the command:

openldr/
  docker-compose.yml
  data/
    my-file.json

The wrapper runs the CLI inside the API container. The data folder is shared with that container, which is why the file must be there. A file elsewhere on your laptop is not automatically available to the server.

For commands that write a file, use the same rule for the output path. From a source checkout, commands use ordinary paths on the computer running the CLI.

Read a command's help before running it for the first time. Import commands write records. Commands that delete or reset data need particular care.

Use Studio on a phone

The main menu starts folded on a phone so the page has more room. Open it when you want to change pages.

1.Open the main menu

Select the menu button at the top left.

Common questions

A page is missing from the menu

Your permissions or selected layout may hide it. Ask an administrator to check both.

A dashboard is empty

The selected data may have no records, or filters may exclude them. You can create a dashboard and configure widgets before records arrive.

The CLI says command not found or file not found

Check that you are in the installation folder and using the correct command prefix for your platform. For input files, check the filename and the data/ prefix.

The CLI cannot connect to Docker

Docker must be running on the server, and your account must have access to it. Ask the server administrator to check these.

I only have access through a browser

Use Studio for the tasks available to your account. Ask an operator to run a command when a guide needs server access.

I need to report a problem

Record the page or command, the action you tried and the exact error message. Give those details to your administrator or support contact.
